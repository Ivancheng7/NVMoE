## 用词约定（写文档时照这个来）

1. **行业有标准中文词的用中文**：上限 / 下限、稳态、常驻、锁页、槽位、分片、页缓存、预填充、
   逐位相同、阻塞点、波动、开销（不用"花销"）。
2. **没有标准中文词的直接用英文原词**，不再自造比喻：wall time、phase profile、arm、tier、gate、
   cursor、golden values，以及本来就一直用英文的 lane、digest、oracle、arena、restage、fan-out、
   manifest、in-flight。
3. **一个词第一次出现时给出英文原词**（常驻 resident、锁页 pinned、逐位相同 bit-exact……）。
4. **一个概念全库一个写法**。读旧记录、旧对话、旧提交信息碰到方言，按下表解码。

## 一、旧写法 → 现在怎么写（我们自己的方言，已停用）

| 旧写法 | 现在怎么写 | 指什么 |
| --- | --- | --- |
| 墙 / 墙钟 | wall time / wall-clock time | 从开始到结束实际等了多久，含空等和搬数据 |
| 上墙 / 落到墙上 / 出现在墙上 | 体现在 wall time 上 / 计入 wall time | 省下的时间真的反映在总等待时间里，而不只在某个计数器里 |
| 相位账 / 逐相位账 | phase profile | 引擎自己记的逐相位耗时，对应结果文件里的 `phase_profile` 字段 |
| 臂（两臂、默认臂、换臂） | arm（两个 arm、默认 arm、换 arm） | 对照实验里的一个版本，开/关各算一个 arm |
| 快档 / 慢档 / 档位 / 两档 | fast tier / slow tier / tier | 同一份代码的两种性能状态（如压缩器每次调用 `7` 对 `15.5 ms`） |
| 门卫 / 闸门 / 门禁 | gate | 决定某条路径走不走的条件判断（如预取只有 CLI 面放行） |
| 天花板 / 地板 | 上限 / 下限 | roofline 意义上的上界 / 下界 |
| 钉死值 / 钉死基线 | golden values / 固定基线 | 任何改动都要过的那组验收值，判据是 `.zcode/verify_baseline.py` |
| 卡点 | 阻塞点 | 卡住进度的具体位置 |
| 收尾（"这一层由谁收尾"） | （这一层的 wall time）由谁决定 | 一层里决定耗时的是哪一段 |
| 归账 / 未归账 | 归属 / 未归属 | 耗时算在哪一项名下 |
| 白干 / 白付 | 无净收益 | 改了但总时间一点没变（旧文档里本来就没出现过） |
| 收口 / 坐实 / 敞口 | 已完成并留证 / 已用实验确认 / 还没盖住的开销 | 写笔记时的口癖，正式文档里不要用 |

同一批一起换掉的还有：`撞上`→碰上、`吃/吃掉`→占用/消耗、`藏身/藏在里面`→重叠窗口/包含、
`砍掉`→减掉、`晃/抖`→波动、`摊在`→落在、`塞进`→放进、`削掉`→消掉、`便宜`→代价小、
`钱/值多少钱`→开销/收益大小、`花销`→开销、`拍板`→决定、`账本会说谎`→这份账会虚报。

## 二、行业标准词的中译（这类继续用中文，但第一次出现给英文原词）

| 我们的说法 | 英文原词 | 指什么 |
| --- | --- | --- |
| 常驻 | resident | 一直待在显存/内存里，用到时已经在，不重新搬 |
| 锁页 | pinned / page-locked memory | 主机内存里不许操作系统挪动的一块，GPU 能直接读 |
| 槽位 | slot | 预先留好的固定位置的缓冲 |
| 分片 | shard | 把大文件切成几块分开存、分开读 |
| 稳态 | steady state | 跑顺之后的稳定速度（不算第一个 token 的冷启动） |
| 逐位相同 / 逐位不变 | bit-exact / bit-identical | 两次结果每一个二进制位都一样，不是"差不多" |
| 页缓存 | page cache | 操作系统自动把读过的文件留在内存里 |
| 探针 | probe / instrumentation | 临时插进去、只负责报数的代码 |
| 判据 | checker / assertion | 判断"数值有没有变"的脚本或断言 |
| 预填充 | prefill | 先把整段 prompt 一趟算完 |
| 逐字生成 | decode | 一个字一个字生成 |

## 三、一直夹在中文里的英文词（不是我们造的，别当成方言）

| 词 | 其实就是 | 指什么 |
| --- | --- | --- |
| lane | stream / worker | 一条并行干活的通道；六条 lane = 六个线程同时读 |
| digest | hash / checksum | 结果的一串指纹，判断两次跑的是不是同一个东西 |
| oracle | reference implementation | 权威的正确实现，拿来当尺子 |
| arena | memory arena / memory pool | 一大块一次申请好、自己切着用的内存 |
| restage | staging copy | 搬家之前先倒一手的那个中转缓冲区 |
| fan-out | parallel dispatch | 一件事同时发给好几个执行者 |
| manifest | manifest | 列着这次用了哪些文件/参数的清单 |
| in-flight | in flight | 已经发出、还没回来的 |

## 四、服务指标的标准名

这一节以后读 vLLM、SGLang 的文档最有用。

| 我们的说法 | 行业标准名 | 指什么 |
| --- | --- | --- |
| 首字 | TTFT (time to first token) | 从发请求到吐出第一个字等了多久 |
| 每 token 时间 | TPOT / ITL (inter-token latency) | 每多吐一个字要多久 |
| 吞吐 | throughput | 每秒出多少字 |

## 六、两组容易混的词

- **页缓存 ≠ prefix caching**。页缓存是操作系统缓存文件内容；prefix caching 是复用不同请求之间
  相同 prompt 前缀的 KV。我们只有前者。
- **我们的 KV cache 是 MLA 压缩过的**（存的是压缩 latent，不是完整的 K/V 头），跟 vLLM 的
  PagedAttention 也不是一回事：我们没有分页，是一块按 token/层预分配的写死池子。
