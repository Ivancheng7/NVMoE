我逐词搜了闭环 / 颗粒度 / 对齐 / 兜底 / 赋能 / 抓手 / 沉淀 / 复盘 / 范式 / 飞轮 / 北极星 / 顶层设计 / 降维等二十多个词，**一个都没有**。真正让他不适的是**腔调**而不是词生僻：`AGENTS.md`、`重启说明.md`、实验记录里那套项目经理汇报口吻——「垂直业务路径」「阶段门禁」「完成标准」「业务基线」「唯一主线」「第一个完成定义」「未决事项」。

**Why:** 这是个 kernel 项目，用汇报项目的姿势说话读起来就假。他要的是能直接拿去干活的记录，不是给上面看的进展报告。

**How to apply:** 写或改中文文档时用工程师记事口吻。已改过一轮的对照：

- 工作优先级 → 先做什么
- 始终优先打通一条垂直业务路径 → 一次只打通一条真实调用链
- 完成标准 → 什么算做完
- 未决事项 → 还没做完的
- 第一个完成定义 → 第一个做完的样子
- 业务基线 → 基线

改腔调时**规则、约束、数字、受保护字符串、记录的事实一律原样保留**——他只嫌姿势，不嫌内容。这类改动很容易顺手把事实改错，别那么干。
