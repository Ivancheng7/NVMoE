2026-09-17 用户明确要求：**以后基本都拿"常驻开"当比较基线**，不要再和代码默认的"常驻关"比。

**Why:** 常驻关那档里固定参数流占着盘，会把任何一项优化的收益吃掉大半——实测：跨层槽位常驻让 `routed.wall` 降 22 ms/层，其中 15–20 ms 被 `fixed` 吃掉，八步墙只降 1–4 s（86.7–87.9 → 83.7–86.8）；同样的改动在常驻开下是 52.5–54.8 → 43.5–43.8 s，收益全落在墙上。拿常驻关当基线会系统性低估改动，甚至得出"没效果/变慢"的相反结论（我犯过一次）。

**How to apply:** 报告与记录里的数字以常驻开为准（当前最快：八步 `43.33 s`、`5.4 s/token`，8 个 digest 与基线相同）；默认配置的表现最多作为"出厂状态"附注一句。做 A/B 时两个二进制都要留档、每次 `drop_caches`、改动前后交错跑（同一份代码当天的墙能差 20 s 以上）。相关：[[flash-0731-baseline-run-recipe]]、[[flash-0731-phase-profile-reading]]、[[concurrent-agent-sessions]]

**2026-09-17：这个"常驻开"已经变成代码默认了，记忆里的框架要跟着改。** 两笔显式决定改的默认（都在交付分支、只影响 `FLASH_BASE` / `FLASH_SERVE` 两个面）：

- `598958e`：`COLIBRI_V4_FIXED_HOST_RESIDENT_GIB` **不设时是 8 GiB**（原来不设 = 0 = 关），`=0` 仍可关。
- `4a72109`：`COLIBRI_V4_FLASH_PROMPT_CHUNK` **不设或 `=1` 是开**，`=0` 回到逐位置扫描。

所以现在"常驻开"不再是需要手动加的开关，而是**默认状态**；要做"常驻关"的对照必须显式 `=0`。别再把它俩当成"代码默认关的实验品"。两个默认都开着时实测：serve 首字 `139.6 → 79.9 s`、每字 `16.7 → 10.0 s`（四跑交替）；单步四个钉死值和 8 步 8 个 digest 不变，峰值 RSS 到 `7.24 GB`。

**一个没量到的数**：常驻开着之后 prompt chunk 自己还剩多少收益——两者重叠（常驻一开，固定参数整个运行只从盘读 1 趟，chunk 原来赚的"少读 4 趟"就被吃掉了）。量过一次但**标签前缀与脚本分支对不上、四跑配置其实相同而作废**：同一配置的四跑自己在 `78.1–82.8 s` 漂（约 6%），比这更小的效应用墙钟看不见，要换 H2D 字节数当判据。写这类 A/B 驱动脚本时，**glob 分支是从头匹配的，传的标签前缀必须真的命中那个分支**，否则会静默跑成默认配置、看起来还像数据。详见 [[flash-0731-serve-path-speed]]
