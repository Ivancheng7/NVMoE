**How to apply**：四条规则——
1. **量完就搬**：一次测量的完成定义是"改动进了交付版"（可以默认关 + 环境开关），否则不开下一个实验。
2. **插桩不复制树**：探针做成交付树里默认关的环境开关，量完留在原地给下一个实验用，不再有"哪棵树能用"的问题。
3. **状态只放一页纸**：一份永远最新的 `现状.md`（钉死值 / 当前默认 / 下一步三件 / 待拍板），新会话只读它；实验记录与交接说明降级成只追加的历史，不为了定向去读。
4. **每批实验预先脚本化**、一次跑完、自带钉死值与 digest 判定（照 `.zcode/serve_ab.sh` + `check_cli.sh`），跑的时候去写下一个改动。
**别砍**：钉死值、逐位比对、结果文件不覆盖旧名字——这些纪律是那 22 小时里唯一没有返工的部分，是数字可信的原因；砍的是围着它的仪式，不是它本身。

**同日已经执行（别重复做）**：`现状.md` 已在仓库根上线（钉死值 / 代码里的当前默认 / 一个 token 花在哪与地板 / 下一步三件 / 待拍板 / 四条规则 / 东西都在哪 / 坑），八份 `交接说明-*.md` 顶部都加了归档指针；范本脚本是 `rust/colibri-cuda/tools/verify_delivery_arm.sh`（同步 + 构建 + 两臂 + 逐位比对 + 相位账，`ARM=<开关变量> LABEL=<标签>` 换臂，跑前自己查机器空不空，`ORDER=off-first` 换跑序，日志写进结果目录——`/tmp` 是 tmpfs，那天丢过两份日志）；**两件未搬改动都已在同日落地**：固定层设备槽位（`7cdd0b1`，交付帧复核 `fixed 1.02→0.73`、逐位不变、`+216 MB`、两个跑序里开着都更快）与压缩器复用池（`7e07056`，digest 逐位不变、`+153 MB`，但收益量不出来，见下）。

**三条新踩到的**：① **跑序有偏差**——先跑的那臂替整批付冷页缓存里 6.7 GB 固定权重的读，单顺序的冷帧差是顺序差不是改动差（换序后才看出来）；② **判改动只在同一批内比**——同样 8 个生成 token 的整请求墙一天里出现过 42.4–52.2 s；③ **别把"某一次快"读成改动生效**：compressor 每次调用在同一天有 `7` 与 `15.5 ms` 两档、与开关无关（7 跑里 1 快 6 慢），那次快档恰好落在开着那一臂上，差点把档位差记成"池子修好了"。所以每个 A/B 都要**把主题相位的状态指标一起报出来**（这里就是 `compressor 每次调用`），两臂档位不一致的那对不许下结论。
