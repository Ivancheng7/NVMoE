## 已讲三节

1. **一个 tiled matmul 的命运** —— decode 形状下算子优化无效（AI=1 vs 平衡点 126），
   prefill 才是战场；benchmark 的常数表决定一切。
2. **tiling 为什么救 matmul** —— 块内复用靠 shared memory，**块间复用靠执行顺序**；
   同 64×64 块，逐行扫→方格扫快 23%；真正救 matmul 的还有 L2（实测 1108–1507 GB/s，
   4.5 倍于 DRAM）。
3. **块该切多大** —— 三条预算（smem 100 KiB/SM、寄存器 65536/SM、线程 1536/SM）
   取最小得 occupancy；加 L2 层后公式预测 3.249 ms、实测 3.42 ms（误差 5%）；
   **256×256 预测 3.249 实测 7.602（错 134%），因为 occupancy=1 时没有延迟隐藏**。

## 关键实测数字

- GEMM 随 batch（权重 128 MiB 排除 L2）：**M=1 时入门 tiled kernel 达理论下限 99%**
  （0.395 vs 0.398 ms）；M=512 时 AI=455 转算力受限。
- 精度 vs fp64 真值：tf32x3 5.28e-05 **最准**（比 ieee 还准 4 倍，比 tf32 准 2400 倍）；
  tf32 1.25e-01；fp16 6.8e-02；bf16 5.7e-01。
- 速度：fp16 35.1 / tf32 17.1 / ieee 10.9 / **tf32x3 6.6 TFLOPS**。
  **tf32x3 只在 TF32÷fp32>3 时划算**（本机 1.57 必输，A100 8× 净赚）——
  是数据中心卡技巧，不是消费级卡的。
- 累加：**1.0 上重复加 1e-8 五千次，增量丢 100%**；32768 个 1e-8 顺序加丢 100%、
  分块加丢 0%。累加器 fp32 vs fp16 在 K=8192 差 10 倍误差。
- tiling：64×64 逐行 3.690 ms → **方格 2.843 ms**（48.3 TFLOPS，**比 cuBLAS 快 27%**）；
  256×256×64 编译失败（需 131072 B smem > 100 KiB）。

## 两个测量陷阱（都踩过，血）

1. **测带宽时数据必须 ≥4 倍 L2。** 曾用 4096×4096 权重（=32 MiB）测出 489 GB/s，
   超过 DRAM 上限——那是 L2 冒充显存。**同类错误在这条学习线上出现了三次。**
2. **测精度时参照物不能和被测量同级。** 曾拿 PyTorch fp32 当真值，把 tf32x3 的优势压平。
