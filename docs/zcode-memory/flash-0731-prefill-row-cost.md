2026-10-01/02 定下的大目标（用户点名"layer_stationary_prefill 那条线上的真问题"）。

**问题**：首字背着整段 prompt 的 prefill，**每行成本等于一个解码 token 的成本**
（服务面 TTFT `15.7 ≈ 8×1.7 + 1.7`；真 32 行 prompt 的 token 0 = `55 s`，占 8 步请求
67.6 s 的大头）。chunk pass（`COLIBRI_V4_FLASH_PROMPT_CHUNK`，默认开）只是让"一次层加载"
服务整段——常驻显存之后层加载本来就免费，**段内每行仍走完整的单行 pass**
（`step_b2_layer` 一次一个位置，`step_real_layer_rows` 只收 rows≤2）。

**实测分解**（2026-10-01 服务面相位账：8 行层 ≈340 ms；2026-10-02 CLI 消融探针复核
`chunk-spine-ab-2026-10-02/`，快档盘：8 行层 **405 ms** = spine（attention 110+router 21）
`16.4 ms/行` + MoE 窗口（routed 137，MLP 86 藏在里面）`17.1` + 填充分摊 `5.6`。两个测量批次
相位结构一致，绝对值随盘档漂）。32 行形状等比放大。

**为什么可以摊**：层内跨行只有 attention 有因果依赖（KV 顺序提交），router/shared/routed
都是"本行 attention 输出 → 本行结果"的行独立计算。

**2026-10-02 量出的天花板与两个硬事实**：
- **spine 和 MoE 窗口几乎等大**（16.4 对 17.1 ms/行）——行间流水的平衡点正好在这：
  理想周期 `~18 ms/行`，层墙 405 → ~155 ms（**−62%**）；8 行预填充 17.4→~6.6 s、
  服务首字 ~14→~9 s 档、32 行 token0 55→~20–25 s。理想值，实现折扣待量。
- **MoE 窗口是固定权重预取填充的藏身地**：消融掉 MoE 后 `fixed` 墙 45→223 ms/层
  （冷读 6.7 GB、下限 44 ms/层追不上变快的层）。流水后 ~155 ms 仍盖得住，但后续再砍
  MoE 窗口必须先看 `fixed` 冒不冒头。
- **手术的依赖事实**：`step_l0_hc_post`（mHC 后处理）属 moe 段、层输出是 [HC,hidden] 的
  mHC 状态（不是 attention 行！第一版探针就栽在这，契约错误 rows==0）；
  `persistent.transaction` 是克隆换回，attention 单独成事务无额外代价；
  fan-out 车道跨位置复用（finish(p−1) 必须在 start(p) 前 join）。
- 探针 `COLIBRI_V4_FLASH_CHUNK_MOE_ABLATE=1`（默认关，输出无效只当探针）留在 exp/prompt-pipeline
  `c467098`；记录 `docs/experiments/2026-10-02-sm120-chunk-spine-ablation.md`。

**2026-10-02 手术第一步已落地（`exp/prompt-pipeline`）**：`step_real_layer_rows` 拆成 attention 相 /
moe 相（待决元组 `AttentionPending` 全 Owned、generic prepared 走外部槽位保 Send），
`step_real_layer_rows` 变成两相逐字组合，**默认面逐位不变（钉死值闸门已过）**。
流水臂 `COLIBRI_V4_FLASH_PROMPT_PIPELINE` 骨架在但**显式拒绝**——前瞻线程借用本层
`loaded.raw.runtime`，而 spawn 的 scope 跨全部层，借用检查器不放行（已解决：cuBLAS/流/scratch
都改成线程内自带、输入每轮拷贝）。两条修法：把流水循环提到 scope 层（优先），或让层运行时
用 Arc 承载。诊断细节 `docs/experiments/2026-10-02-sm120-layer-phase-split.md` 未决 1。

**2026-10-02 深夜接线一轮（`ee852bf..54be92d`，未编过，已回退到 `e8ea46c` 的可编译状态）**：
前瞻线程的 cuBLAS/流/attention scratch 已全部改成线程内自建、输入按值捕获、运行时用
`SendRuntimePtr` 裸指针封装（签名层已无生命周期错）——但 spawn 仍报一个 `*const …` 不 Send，
**构建 wrapper 会把诊断截成一行（`--json` 被丢、human 渲染器在本机 nightly ICE），没能定位是哪个捕获**。
二分已排除 attention scratch 与 context；主嫌疑 `module: &LoadedModule`（既有的车道从不直接捕获它）。
下一步：用 `fn assert_send<T: Send>()` 对每个捕获做断言把类型钉出来。

**2026-10-02 收尾：流水臂已接线并真跑——数值逐位正确、但更慢（回归）**（`exp/prompt-pipeline`）：
服务面一个引擎 3 请求 × 两臂两轮交错，id 串四跑全同；TTFT 关 `16.5/14.6/13.7`、开
`24.2/15.6/15.2` s（**+0.9~+7.7，是回归**），消融模型的 −62% 没兑现，旗标保持默认关。
接线路上踩掉的四个真坑（都已修，详见记录）：裸指针包装挡不住 edition 2021 精确捕获
（改传 `usize` 地址）、新入口把 runtime 生命周期绑到 module 的 `'module`（借用拖长整层）、
每轮重建 cuBLAS 会话（每次重校验 105 MB 库、每层 +1.88 s → 改共享地址）、层墙守卫对重叠
不适用（开例外）。**回归原因已由相位账定性**：前瞻线程的 attention 相 107→291 ms/层（2.7×）——设备步被
主线程的 MLP + 六条专家内核在同一块 GPU 上抢占，「attention 与 MoE 重叠」的前提不成立；
**别把读盘当空闲资源**（fan-out 里它本来就藏在同行车道窗口内）。**attention 构成已量出**：chunk 层 attention 墙 109.8 ms = 设备执行 105.5 + commit 4.4 + 主机≈0
（CLI 面，`attention-steps-2026-10-02/`）——**几乎全是 GPU 干活**，所以叠进同样占 GPU 的 MoE 窗口
只能排队。这条线的正确方向不是换重叠顺序，而是**减少 GPU 工作本身**（车道顶起的 MLP ~10 ms、
六个专家内核）或回到少读少算（A2、批内核）。

**两条改进路线**（都要拆 `step_real_layer_rows` 的层内顺序，逐位不变是硬约束）：
1. **行间流水**（先打）：把"下一行的 spine"藏进"当前行的 MoE 窗口"（纯调度、逐位不变由
   构造保证）；天花板见上。
2. **行并行批内核**（流水的下一站）：MoE 窗口里的 MLP/router 对整段行批量做（保 K 序），
   把 `17.1 ms/行` 的车道链进一步压向读盘下限。

**前置事实**：A2 缓存（默认关）是层内跨行/跨 token 专家读去重的现成机制，但 token 0
"第一遍全 miss"还倒贴 1.2 s；fan-out 只接 rows==1。lane 争用线已关（[[flash-0731-routed-fanout]]），
服务面常驻重建已修（[[flash-0731-fixed-resident-vram]]），都不是这一段的钱。

相关 [[flash-0731-per-token-floor]]、[[flash-0731-phase-profile-reading]]。

## 2026-10-02 收口：两条路线都试了，都够不到墙；层墙是个 `max`

八行预填充趟、单请求、命令行、3 轮交错，结论（全在
`docs/experiments/2026-10-02-sm120-prompt-pass-what-binds.md`）：

**层墙 ≈ `attention + router + max(MoE 窗口, 固定权重读时间)`**（三处独立测量都拟合得上，
残差最大 36 ms，当近似用）。`attention + router` ≈ `130 ms/层` 不碰盘、是地基。

**五笔单侧改动全部白干**，因为都是把一侧压下去、另一侧顶上来：

| 改动 | 目标量动了 | 层墙 |
| --- | --- | --- |
| 削 MLP（行并行批，`CHUNK_MLP_BATCH`） | `shared.main 84.7 → 4.09`（逐位相同） | **+21 ms** |
| 削 lane 内核（消融） | `lane_max 42.4 → 32.2` | −9 ms |
| 缩身份缓存到一层（16/32/64 槽） | 读的账 `585 → 462~513` | 打平~更慢 |
| 专家提前读（`CHUNK_READAHEAD`，WILLNEED） | `lane_max 45.7 → 37.7` | **+10 ms** |
| 固定读并行（3 线程，**已默认开**） | 读 `300–343 → 192–210 ms`（0.5→0.78 GB/s） | **−9.7 ms（−2.3%）** |

**绑定项是读，而且是两侧一起**：lane 链里读占最慢那条 lane 墙的 67%
（`LANE_PROBE`：墙 25.8 = 读 17.4 + 上传 3.5 + 内核 2.0 + 未归属 2.9，**线程启动等待恒为 0**）；
固定权重读只有 `0.5–0.8 GB/s`，而**同一份逐张量 plan 离线 4 条流是 3.51 GB/s**（形状不是根因，
并发不足才是，差额被同时段的 612 MB/layer 路由读吃掉）。

**下一步**：两侧一起压——① 同层专家读去重（48 次使用只对应 **21.7 个不同专家**，`CHUNKROUTES`
探针实测，每层 612 → 277 MiB；K2 的批臂已经提供前提：一层之内所有行的 attention 相先跑完，
路由在读第一个专家前就已知，可每个专家只读一次、只上传一次）；② 固定读继续提并发。
只做①预期 `404 → ~330 ms/层`（−18%），两项都做才到 `~260`（−36%）。

**教训两条（都是这程踩的）**：
- **别拿 `lane_max` 一个数下结论**——它是跨 8 个位置取的最大值，我因此在表八处写下"读不是绑定项"，
  后来被 `LANE_PROBE` 的分布推翻。**这条链要看分布。**
- **`capture_layer_trace` 在 CLI 面恒为真**：把它当实验臂的闸门会让臂在命令行静默失效
  （踩过一次，白跑一批）。它只决定逐层 digest 要不要写进结果 JSON。

## 2026-10-02 深夜：同层专家去重做出来了，但"没有东西可去重"

分组去重臂已落地（`CHUNK_EXPERT_DEDUP`，默认关，提交 `d8f27c0`）：一层 8 行的路由都已知，
每个不同专家只读一次只上传一次，再按原槽位逐个使用位跑同样的 matvec。
**按设计工作**（载入 `48 → 21.7`、上传的和 `139.5 → 70.7 ms/层`、三轮回合逐位相同），**层墙打平**。

**直接量盘（`/proc/diskstats` 的 `sdd` 扇区读增量）**：一趟预填充 `all` `20.0/20.6 GB`、
去重臂 `20.4/20.4 GB`——**差 0.5%**。原因：**同层重复的专家读早就命中页缓存**，
盘上只走"不同专家集合"（约 `321 MB/层`），而引擎账本请求的是 `48 × 13.37 = 642 MB/层`。

由此两条**必须记住的**：
- **引擎的"请求账"不是盘流量。** 载入次数/`source_bytes` 记的是"读了几次"，
  同层重复会被页缓存吸收。**要报盘流量就用 `/proc/diskstats` 量**（`assist` 脚本
  `.zcode/run_k4_diskbytes.sh`）。我此前"48 次使用 → 21.7 个专家，能省 2.2 倍盘读"的推断
  就是这么错的。
- **一趟预填充真实只搬 `20.4 GB`、聚合 `1.16 GB/s`**，而这台盘冷读上限 `3.4–3.9 GB/s`——
  **只用了三成**。所以预填充**不是带宽绑的**，是"突发 + 等"绑的（每个位置 6 条 lane 一起读、
  读完盘就空着）。**宽度不能靠加**：6 → 22（一版读完全部不同专家）时每条读窗口涨 3 倍、
  整层慢 8%（`read` 的和 `594 → 1622 ms`）。**6 宽是这台盘喜欢的并发度。**

**下一类实验**（不是继续在单个位置里挪时间）：把一层 8 个位置的 MoE 串行改成
**共用一个不空转的 6 宽读队列**，让盘在整层里都有活。

## 2026-10-02 深夜（续）：做成了——预填充趟 −15%，而且盘上字节一个字没变（`0f955f4`）

上一段说"去重按设计工作但层墙打平"——**原因是那版做成了"每 6 个一轮、轮间 join"，
只是把空转搬了个地方**。改成**恰好 `width` 条 worker 从一根共享游标上一直取活**
（一个 worker 做完一个专家——读、上传、跑完它所有使用位——再取下一个）之后：

| 臂 | 预填充趟 outer | 8 步 e2e |
| --- | ---: | ---: |
| `all`（默认） | 393.69 ms/层 | 29.78 s |
| 批臂（只有结构） | 398.61 | 30.10 |
| **`pool`（池子，不去重）** | **361.20** | **29.10** |
| **`pool` + 去重** | **334.65** | **27.50** |

**两笔钱分得开：池子本身 `−37.4 ms/层`，池子上再去重 `−26.5 ms/层`。** 四臂全部逐位相同。
而 `/proc/diskstats` 量出来**盘上搬的还是那 20.5 GB**——**全部来自"盘不再空转"，
不是少了字节**。宽度扫 4/6/8/10/12：6 与 10 并列最好、其余在噪声内，**不需要新旋钮**。

开关：`CHUNK_MLP_BATCH`（结构：attention 先跑完 + 批量 MLP）、`CHUNK_EXPERT_GROUP`（池子）、
`CHUNK_EXPERT_DEDUP`（池子按不同专家走），**三个都默认关**。翻默认前要补：服务面首字、
真 32 token prompt、以及 `pool` 两臂在**解码稳态**上那 `+1.4 ms/层`（本该不相关，大概率噪声，
但没追）。

**这条也是那六笔"白干"的出口**：前面每一笔都动了某个量、层墙不动，因为**层墙跟的不是某个量，
而是"突发+等"的结构**。改结构才有钱，调参数不值钱。

`V4_ROUTED_EXPERT_BYTES` ≠ 一条 lane 实际读的字节（大 2.6 倍），要实际字节用 `lane.h2d_bytes()`。
